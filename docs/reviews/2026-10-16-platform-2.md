# Code review — Platform 2.0 (2026-10-16)

**Scope:** everything added for [Platform 2.0](../specs/platform-2.0.ru.md):

- **Module platform:** manifest, dependencies (`requires` / `enhances`), module versions, enable prompts.
- **Admin documentation and System:** per-module admin docs, the System report.
- **Demo data:** the demo framework, plus seeds for every module.
- **Guided tours:** tours and their `data-tour` anchors.
- **Themes:** the theme catalog and custom backgrounds.
- **Org structure:** org units and positions.
- **Employees module.**
- **AD directory module.**

**Method:** two read-only reviewers. One covered the platform, demo, tours, themes, org and employees work (findings R). The other covered the AD directory module (findings D). Every finding was checked against the code, with a concrete failure scenario.

**Status:** all 30 findings fixed on 2026-10-16, with tests. The one exception is part of R3, explained below.

## R. Platform, demo data, org structure, employees, experience

| ID | Area | Defect | Status |
|---|---|---|---|
| R1 | Demo data | Demo approvals could be submitted under a real route and decided on behalf of real people. Notifications sent during a seed reached real users. | Fixed. When a real route is in force, demo documents stay drafts; this covers procurement, contracts and warehouse. `decideDemo` acts only as demo people. `demoScope` limits notifications to demo users, in the app only. |
| R2 | Org | The people picker returned employees to anyone. | Fixed. Employees are shown only to org managers and to people who can see the directory. |
| R3 | Employees | Linking or unlinking a portal account needed only HR rights, and worked on accounts with more access. | Fixed. It now needs `employees.hr` and `users.manage`, and is refused for accounts with more access than the actor. Setting `manager_id` explicitly is deliberately left unrestricted. |
| R4 | Org | `setUserUnit` could move an account with more access than the actor. | Fixed |
| R5 | Org | A parent change in `updateUnit` raced `moveUnit`, so a cycle in the tree was possible. | Fixed. The same tree lock is used, followed by a re-read and a cycle check. |
| R6 | Themes | Uploading a new background deleted the old picture before the new one was stored. | Fixed |
| R7 | Employees | The clearance reminder job notified about demo employees. | Fixed |
| R8 | Dashboard demo | The purge removed a default layout that an admin had saved after seeding. | Fixed |
| R9 | Modules | Module requirement checks ran on stale settings and could race each other. | Fixed. Fresh settings are read under an advisory lock. |
| R10 | Demo | Concurrent seed and purge runs on the same module interleaved. | Fixed. A per-module lock serializes them. |
| R11 | Themes | The server accepted themes the admin does not offer, and custom-theme settings while custom themes are off. | Fixed (`themeAllowed`) |
| R12 | Themes | The background converter had no limits. | Fixed. Each person gets one job at a time and 10 per hour; at most 6 people can queue. |
| R13 | Org | Position headcounts were visible without directory rights. | Fixed |
| R14 | Employees | Cards showed dismissed managers. | Fixed |
| R15 | Org | Renaming a position did not update linked accounts. | Fixed |
| R16 | Tours | The spotlight kept pointing at an anchor that was gone. | Fixed. The anchor is looked up again, or the spotlight is hidden. |

## D. AD directory module

| ID | Sev | Defect | Status |
|---|---|---|---|
| D1 | Critical | Linking an AD account to a portal user did not check the target. A user with `users.manage` could point their own AD login at the superadmin account. | Fixed. Linking needs `assertCanManage`, a superadmin target is refused for non-superadmins, and refusals are journalled. |
| D2 | High | The create-user wizard could add the new account to protected (adminCount) groups. | Fixed |
| D3 | M | Group membership edits did not check whether the member was protected. | Fixed |
| D4 | M | Folder-access (`sg_`) groups could be moved or edited through the API. | Fixed. These groups are now managed only in File server. |
| D5 | M | When StartTLS was configured, the acting admin's password was still sent in clear for ordinary writes. | Fixed. Every actor bind and `verifyBind` now uses StartTLS. |
| D6 | M | A password reset that succeeded was reported as failed when the follow-up flags step failed. | Fixed. The outcome is now `partial`, with the separate steps listed. |
| D7 | M | Links made in demo mode between employees and AD accounts survived the demo purge. | Fixed. The purge reverts them from the journal. |
| D8 | M | Expanding a tree node fetched every object below it. | Fixed. Counts are capped at 2000 per child, at most 4 searches run at once, and `hasChildren` is found cheaply. |
| D9 | L | The object list was cut to 5000 before filtering. | Fixed. Filtering runs before the cut, and the UI shows a banner when results are cut. |
| D10 | L | Bulk actions did one service bind per object. | Fixed. Objects are read in batches with `byDns`. |
| D11 | L | Display names over 64 characters broke user creation. | Fixed (`cnFor`) |
| D12 | L | DN comparison collapsed internal whitespace. | Fixed |
| D13 | L | The module showed DNs from outside the root, and the login checks needed only `ad.view`. | Fixed. Those DNs are now hidden, and the login checks need `ad.manage`. |
| D14 | L | The browser password checklist missed the server's name rule. | Fixed |
| — | i18n | `FA_AD_*` errors were not mapped to `AD_*`. | Fixed |

## Decisions recorded

- **AD module without AD.** It can be enabled without the AD integration, using the requirement `demo: true`. In that state it shows demo data, or returns `AD_OFF`, and never calls LDAP. The spec is updated accordingly.
- **Explicit manager on an employee card** (`manager_id`) is not restricted. Setting managers is normal HR work.
