# ТЗ: бизнес-процессы портала — Согласования, Закупки, Договоры, Поручения

**Версия:** 1.0 · **Дата:** 13.10.2026
**Назначение:** набор модулей «как лего» для компаний любого профиля. Модули включаются по отдельности и работают как сами по себе, так и в связке с уже имеющимися: Задачами, Контрагентами, Файлами, Чатом, CRM и Мастерпланом.

---

## 1. Цели

1. **Одна точка входа для руководителя.** На странице «Ждёт меня» собрано всё, что требует его решения: заявки, договоры, оплаты и поручения. Срочное стоит сверху.
2. **Прозрачный путь любой заявки и любого договора.** Видно, кто подал, кто согласовал, где документ сейчас и сколько он там лежит.
3. **Сроки под контролем.** Просроченное подсвечивается красным, приближающееся — жёлтым. Напоминания и эскалация уходят автоматически.
4. **Вопросы задаются там же, где документ.** Директор спрашивает прямо в карточке, ответ возвращает документ на согласование. Ничего не теряется в мессенджерах.
5. **Универсальность.** Маршруты, категории, уровни срочности и обязательные поля настраиваются без программиста.

## 2. Принципы удобства (обязательны для всех экранов)

- **«Три клика до решения».** Из уведомления или со страницы «Ждёт меня» решение принимается за 1–2 действия: «Согласовать» или «Вопрос», без перехода по экранам.
- **Боковая карточка поверх списка.** Документ открывается справа, список остаётся на месте. Клавиши ↑/↓ листают документы.
- **Цвет означает срок.** Красный — просрочено, жёлтый — меньше 24 ч (настраивается), серый — без срока, зелёный — готово.
- **Срочность видна сразу:** «Критично», «Срочно» или «Обычно», с иконкой. Список по умолчанию сортируется по срочности, затем по сроку.
- **Быстрое создание.** Форма открывается одной кнопкой. Обязательны только суть, сумма и вложение, остальное можно дополнить позже. Черновик сохраняется сам.
- **Фильтры-чипы со счётчиками** над списком: «Мои», «Ждут меня», «Срочные», «Просрочено», «В работе», «Отработано». Набор фильтров можно сохранить как вид.
- **Мобильная версия полноценная.** Согласовать, ответить или сфотографировать счёт можно с телефона.
- **Даты и время** показываются по региональным настройкам человека (`docs/datetime.md`), суммы — с валютой и разделителями.
- **Единый стиль портала:** antd 5, переменные темы, светлая и тёмная тема, пустые состояния с подсказкой, что делать, скелетоны при загрузке.
- **Все действия журналируются.** На странице документа вкладка «История».

## 4. Согласования (сервис ядра)

### 4.1 Понятия

- **Маршрут** — шаблон: упорядоченные **этапы**. Каждый этап — один или несколько согласующих: «все» или «любой из».
- **Согласующий:** конкретный человек, роль, группа или «руководитель автора».
- **Условия этапа** проверяются по полям документа: сумма больше X, категория, проект, юрлицо. Если условие не выполнено, этап пропускается.
- **Процесс согласования** — экземпляр маршрута для конкретного документа.

### 4.2 Решения согласующего

| Решение | Что происходит |
|---|---|
| Согласовать | Этап закрывается, когда все или любой из согласующих согласовали; документ идёт на следующий этап. После последнего этапа документ получает статус «Согласовано» |
| Отклонить | Обязателен комментарий. Процесс завершается со статусом «Отклонено» |
| Вопрос | Обязателен текст. Документ переходит в «Нужен ответ» у автора или указанного человека. Ответ, необязательно с изменением документа, возвращает документ на тот же этап |
| Вернуть на доработку | Документ возвращается автору. После правок автор отправляет его заново, и согласование начинается с первого этапа (или с текущего — настраивается) |
| Делегировать | Передать решение другому человеку с комментарием |

Автор может **отозвать** документ, пока его не согласовали.

### 4.3 Сроки и эскалация

- **Срок реакции этапа** задаётся в часах и зависит от срочности. Например: «Критично» — 4 ч, «Срочно» — 24 ч, «Обычно» — 72 ч. Рабочее время пока не учитывается.
- За 25 % срока до конца приходит напоминание. После срока документ подсвечивается красным, и уходит уведомление эскалации тому, кто указан в маршруте (по умолчанию — администраторам модуля).
- **Замещение:** человек указывает заместителя на период, например на время отпуска. Его этапы в этот период видит и может решать заместитель.

### 4.4 «Ждёт меня»

- Отдельная страница в меню приложений («Входящие»), виджет на дашборде и счётчик на значке.
- Группы: «Просрочено», «Сегодня», «Остальные» (по срочности). Фильтр по модулю.
- В строке: модуль, номер, название, сумма, автор, срок, срочность и кнопки «Согласовать», «Вопрос», «Открыть».
- Массовое согласование: несколько отмеченных документов одним действием, с подтверждением.
- Вкладки: «Ждёт меня», «Мои на согласовании», «Решённые мной».

### 4.5 Настройки

- **Конструктор маршрутов** для каждого модуля и типа документа: этапы перетаскиваются, условия задаются полями формы. Есть предпросмотр: «для заявки на $5 000 категории "Оборудование" маршрут будет таким».
- **Уровни срочности:** названия, цвета, сроки реакции.

### 4.6 API для модулей

Модуль регистрирует тип документа: ключ, название, поля для условий, функцию проверки доступа и колбэк смены статуса. После этого он вызывает «запустить», «отозвать», «перезапустить». События `approval.*` уходят в центр уведомлений и вебхуки.

## 5. Закупки (модуль)

### 5.1 Заявка на закупку

| Блок | Поля |
|---|---|
| Суть | Название, описание, категория (справочник), позиции (наименование, кол-во, ед., цена, сумма) или одна общая сумма |
| Деньги | Сумма, валюта, юрлицо-плательщик (справочник), условия оплаты (100 % / аванс X % / постоплата) |
| Сроки | Срочность, «оплатить до», «поставить до» |
| Поставщик | Из Контрагентов или текстом, контакты |
| Привязки | Проект или объект (Мастерплан), сделка (CRM), договор (модуль Договоры) — каждая показывается, только если модуль включён |
| Документы | Счёт на оплату (обязателен перед отправкой, если так настроено), КП, спецификация, фото. Можно загрузить или выбрать из Файлов |
| Ответственный | Автор по умолчанию; можно назначить снабженца |

### 5.2 Статусы

**Черновик** → **На согласовании** (↔ **Нужен ответ**) → **Согласовано** → **К оплате** → **Оплачено частично** / **Оплачено** → **Поставлено** → **Закрыто**.
Боковые статусы: **Отклонено** и **Отменено**.

- «К оплате» ставится автоматически после согласования. Бухгалтер видит заявку в реестре оплат.
- Оплата отмечается так: дата, сумма, способ, номер платёжки, файл платёжки. Можно отметить несколько частичных оплат. Статус «Оплачено» ставится, когда сумма оплат равна сумме заявки.
- Поставку подтверждает ответственный или автор. Можно приложить накладную и акт и указать, что поставлено частично.

### 5.3 Экраны

1. **Список** с таблицей и канбаном по статусам.
   - Фильтры-чипы: «Мои», «Ждут меня», «Срочные», «Просрочено», «К оплате», «Отработано».
   - Поиск по номеру, названию и поставщику.
   - Колонки: №, название, сумма, поставщик, срочность, статус, «оплатить до», «поставить до», ответственный.
2. **Карточка (боковая панель):**
   - шапка: №, статус, срочность, сумма;
   - полоса пути согласования: этапы с аватарами, отметками и временем ответа;
   - кнопки решения;
   - вкладки «Детали», «Документы» (с предпросмотром счёта PDF или картинки), «Обсуждение» (чат), «Оплаты», «История».
3. **Реестр оплат (бухгалтер):**
   - группы «Просрочено», «Сегодня», «На неделе», «Позже»;
   - итоги по валютам;
   - отметка оплаты прямо из строки;
   - выгрузка в Excel (CSV).
4. **Форма создания:** одна колонка, сверху суть и сумма. Счёт можно перетащить или сфотографировать. После сохранения кнопка «Отправить на согласование».
5. **Сводка (для руководителя):**
   - суммы по статусам, категориям и месяцам;
   - средний срок согласования;
   - просроченные.

### 5.4 Права

| Право | Кому |
|---|---|
| `procurement.create` | Сотрудникам, которые подают заявки |
| `procurement.view_all` | Руководству; остальные видят свои заявки, заявки своей группы и те, где они согласующие |
| `procurement.pay` | Бухгалтерии: реестр оплат, отметка оплаты |
| `procurement.admin` | Справочники, маршруты, настройки |

### 5.5 Уведомления

Заявку отправили мне на согласование. По моей заявке задали вопрос, согласовали или отклонили. Заявка ждёт оплаты (бухгалтерии). Срок оплаты или поставки скоро истекает или прошёл. Заявку оплатили (автору).

## 6. Договоры (модуль)

### 6.1 Карточка договора

| Блок | Поля |
|---|---|
| Основное | Номер, название, тип (поставка, услуги, аренда, подряд, трудовой и др.), направление (с поставщиком / с клиентом), контрагент, юрлицо |
| Деньги | Сумма (или «рамочный»), валюта, условия оплаты |
| Сроки | Дата заключения, начало, окончание, автопролонгация (да или нет, срок уведомления об отказе) |
| Ответственные | Юрист, ответственный от бизнеса |
| Документ | Версии файла: каждая с автором, датой и комментарием; текущая версия помечена |
| «На что обратить внимание» | Список рисков юриста: текст, пункт договора, важность (высокая, средняя, низкая), статус (открыт, принят, исправлен) |
| Привязки | Заявки на закупку, сделка CRM, объект Мастерплана |

### 6.2 Статусы

**Проект** → **На согласовании** (↔ **Нужен ответ**) → **Согласован** → **Подписан** → **Действует** → **Истекает** (автоматически за N дней) → **Завершён**.
Боковые статусы: **Отклонён** и **Расторгнут**.

### 6.3 Работа с правками

- **Обсуждение** — чат договора. Сообщение можно привязать к риску или пункту.
- **Новая версия:** загрузка файла с комментарием «что изменено». Все видят ленту версий, любую версию можно скачать или открыть.
- **Риски** — чек-лист юриста. Согласующий видит открытые риски высокой важности рядом с кнопкой решения.

### 6.4 Экраны

1. **Реестр договоров:**
   - фильтры-чипы: «Мои», «Ждут меня», «Действуют», «Истекают за 30 дней», «Без подписанной версии», «Архив»;
   - колонки: №, контрагент, тип, сумма, срок до, статус, ответственный.
2. **Карточка:** шапка, путь согласования, вкладки «Обзор» (поля, риски), «Версии», «Обсуждение», «Связи», «История».
3. **Календарь окончаний** — какие договоры истекают по месяцам.

### 6.5 Напоминания

За 30 и за 7 дней до окончания, а также до даты уведомления об отказе от пролонгации. Уходят ответственному и юристу.

### 6.6 Права

`contracts.create`, `contracts.view_all` (иначе видны свои, договоры своей группы и те, где человек согласующий), `contracts.legal` (риски, статусы «Подписан» и «Расторгнут»), `contracts.admin`.

## 7. Поручения (доработка Задач)

1. **«Принять в работу».** Новая задача, которую поставили другому человеку, ждёт принятия. Исполнитель нажимает «Принять» (можно с комментарием) или «Обсудить». В ленте задачи остаётся отметка «Принято … в …».
2. **Срок принятия:** настройка проекта или глобальная, по умолчанию 24 ч, для «важных» задач — 4 ч.
   - Не принята в срок — задача горит красным с меткой «Не принята N ч».
   - Уходит напоминание исполнителю и уведомление постановщику.
3. **Просрочка исполнения** работает как раньше: отдельная красная метка «Просрочено на N дн.».
4. **Поручения от руководства.** Вкладка или фильтр «Поручения»: задачи, где постановщик из группы «Руководство» (группа настраивается) или задача помечена флажком «Поручение».
5. **«Мои задачи»:** сверху группа «Ждут принятия». У постановщика — фильтр «Не приняты».
6. На странице «Ждёт меня» задачи, ждущие принятия, показываются вместе с согласованиями.

## 8. Общие требования

- **Нумерация:** префикс модуля и номер: `ЗК-0001`, `ДГ-0001`; префикс настраивается.
- **Поиск по порталу (Ctrl+K)** находит заявки и договоры.
- **Экспорт** списков в CSV/Excel с учётом прав. Колонки только видимые.
- **API и вебхуки** по общим правилам портала: `procurement.*`, `contracts.*`, `approval.*`.
- **Безопасность:** права проверяются на сервере. Суммы и вложения видят только те, кому положено. Вложения отдаются так же, как в Файлах (sandbox, nosniff).
- **Производительность:** список на 5 000 документов открывается быстрее 1 с (пагинация на сервере).
- **Языки:** русский и английский.
- **Справка:** раздел справки для каждого модуля и подсказки (?) на сложных полях.

## 9. Критерии приёмки (MVP)

1. Сотрудник за 1 минуту создаёт заявку со счётом с телефона и отправляет на согласование.
2. Директор получает уведомление и со страницы «Ждёт меня» задаёт вопрос в 2 клика. Сотрудник отвечает, директор согласует.
3. После согласования заявка появляется в реестре оплат бухгалтера. Бухгалтер отмечает оплату с платёжкой, автор получает уведомление.
4. Заявка, не согласованная в срок, горит красным на всех списках, согласующему уходит напоминание, назначенному человеку — эскалация.
5. Юрист загружает договор, добавляет 3 риска, коллега загружает новую версию с комментарием. Обсуждение и версии видны всем участникам.
6. За 30 дней до окончания договора ответственному приходит напоминание. В реестре договор попадает в «Истекают».
7. Директор ставит поручение «найти администратора, срок 5 дней». Если исполнитель не принял его за 24 ч, задача горит красным с меткой «Не принята», директор получает уведомление.
8. Фильтры «Срочные / Просрочено / В работе / Отработано» работают во всех трёх модулях и показывают счётчики.
9. Всё работает в светлой и тёмной теме, на телефоне, на русском и английском.

## 10. Решения по умолчанию (уточнить у заказчика)

| Вопрос | Решение в MVP |
|---|---|
| Маршрут | Один этап «Директор» (роль или группа). Пороги сумм и дополнительные этапы — через конструктор |
| Бюджеты | Нет (v2) |
| Оплата | Отметка в портале и выгрузка реестра; интеграция с 1С и банком — v2 |
| Юрлица | Справочник юрлиц; по умолчанию одно |
| Валюты | USD, KGS, RUB (как в Мастерплане) |
| Срочность | Критично 4 ч · Срочно 24 ч · Обычно 72 ч |
| Принятие поручения | 24 ч, для важных — 4 ч |
| Каналы уведомлений | Как у всего портала: портал и push, почта, Telegram, по настройкам человека |

## 11. Этапы реализации

1. **Этап A:** сервис Согласований и страница «Ждёт меня» · Поручения в Задачах. Делается параллельно.
2. **Этап B:** Закупки и реестр оплат · Договоры. Делается параллельно, на основе API Согласований.
3. **Этап C (v2):** бюджеты, интеграция с 1С и банком, шаблоны договоров, рабочий календарь для сроков, электронная подпись.
